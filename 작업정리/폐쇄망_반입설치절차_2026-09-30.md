## 1. 패키지 만들기 (인터넷 되는 PC)

```sh
git switch feature/ollama
npm ci                                   # 처음 한 번
bash scripts/ollama-offline/package.sh   # 번들 빌드 + Node 런타임 내려받기 + tar.gz
```

- 결과: `dist-offline/gemini-cli-ollama-<버전>-<커밋>-linux-x64.tar.gz` (약
  69MB)와 `.sha256`
- 이름에 `-dirty`가 붙으면 커밋하지 않은 수정이 섞인 것이다. 반입본은 커밋 후
  만든다.
- Node 런타임은 개발 PC와 같은 버전(`node --version`, 현재 v24.19.0)의 공식
  linux-x64 배포본을 내려받아 SHA256을 확인한 뒤 넣는다. 다른 버전은
  `--node-version v24.x.y`.
- 이미 번들을 만들었으면 `--skip-bundle`.

패키지 내용:

| 경로                                   | 내용                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------- |
| `bin/gemini`                           | 실행기 - 패키지 안의 Node로 번들 실행, `config/gemini.env`를 읽음         |
| `install.sh`                           | 체크섬 확인, `runtime/node` 풀기, 설정 샘플 복사                          |
| `bundle/`                              | CLI 번들(`gemini.js` 외) + `vendor/ripgrep/rg-linux-x64`(`grep_search`용) |
| `runtime/node-<버전>-linux-x64.tar.gz` | Node 런타임 (xz가 없는 서버를 위해 gzip)                                  |
| `config/gemini.env.sample`             | `GEMINI_OLLAMA_*` 기본값                                                  |
| `config/settings.json.sample`          | `~/.gemini/settings.json` 샘플 (설계문서 5절과 같음)                      |
| `README.md`, `VERSION`, `SHA256SUMS`   | 요약 안내, 빌드 정보, 파일별 체크섬                                       |

## 2. 반입

- `.tar.gz`와 `.tar.gz.sha256`을 함께 반입한다.
- 반입 후 확인: `sha256sum -c gemini-cli-ollama-*.tar.gz.sha256` (Windows에서
  만든 `.sha256`은 파일명 앞에 `*`가 붙지만 Linux `sha256sum -c`가 그대로
  읽는다)

## 3. 설치 (폐쇄망 서버)

```sh
tar -xzf gemini-cli-ollama-*-linux-x64.tar.gz -C /opt      # 설치 위치는 자유
cd /opt/gemini-cli-ollama
sh install.sh
echo 'export PATH="/opt/gemini-cli-ollama/bin:$PATH"' >> ~/.bashrc && . ~/.bashrc
```

- 서버에 Node가 없어도 된다(패키지 런타임만 사용).
- `~/.gemini/settings.json`이 이미 있으면 덮어쓰지 않는다.
  `config/settings.json.sample`과 비교해 `security.auth.selectedType: "ollama"`,
  `tools.exclude`, 압축 설정을 옮긴다.
- 여러 사용자가 쓰면 `install.sh`를 사용자마다 한 번씩 실행하거나
  `settings.json`만 각자 복사한다.

## 4. 설정

`config/gemini.env`에서 확인·수정한다(셸에 이미 설정된 값이 우선).

| 변수                     | 기본값                   | 비고                                        |
| ------------------------ | ------------------------ | ------------------------------------------- |
| `GEMINI_OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | 같은 서버면 `localhost` 대신 `127.0.0.1`    |
| `GEMINI_OLLAMA_MODEL`    | `qwen3-coder:30b`        | `ollama list`의 이름과 같아야 함            |
| `GEMINI_MODEL`           | = 모델                   | 화면 표시용. `auto` 금지(매 턴 라우터 호출) |
| `GEMINI_OLLAMA_NUM_CTX`  | `32768`                  | SQL 튜닝 REST API와 같은 값                 |

## 5. Ollama 서버 확인 (설치 전·후 한 번)

```sh
curl -s $GEMINI_OLLAMA_BASE_URL/api/version          # 0.35.0 기준으로 검증함
ollama show qwen3-coder:30b --modelfile | grep -E '^(RENDERER|PARSER)'
```

- `RENDERER qwen3-coder`, `PARSER qwen3-coder` 두 줄이 있어야 도구 호출이
  `tool_calls`로 온다 (공식 배포본에는 있음). GGUF만 반입해 `ollama create`로
  만들었다면 Modelfile에 두 줄을 넣는다.
- CLI를 Ollama와 **다른 서버**에서 쓰면 Ollama가 외부 주소로 열려 있어야
  한다(`OLLAMA_HOST=0.0.0.0`). 127.0.0.1에만 열린 Ollama는 다른 호스트 이름으로
  온 요청을 `403 Forbidden`으로 막는다(검증 중 확인).
