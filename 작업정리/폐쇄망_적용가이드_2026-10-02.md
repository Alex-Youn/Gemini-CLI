# 폐쇄망 적용 가이드 (2026-10-02)

사용자 PC의 Gemini CLI가 GPU 서버의 REST API를 거쳐 Ollama를 쓰도록 폐쇄망에
적용하는 절차다.

```
사용자 PC [VS Code 터미널 + gemini] --HTTP 9300--> GPU 서버 REST API [/ollama 중계] --localhost:11434--> Ollama qwen3-coder:30b
```

관련: `작업정리/사용방식_결정_REST_API_Ollama중계_2026-10-02.md`(결정·구현
기록), `작업정리/폐쇄망_반입설치절차_2026-09-30.md`(Linux 서버에 CLI를 설치하는
경우)

## 1. 반입할 파일

| #   | 파일                                                 | 대상      | 용도                                    |
| --- | ---------------------------------------------------- | --------- | --------------------------------------- |
| 1   | `sqltune-rag-java-1.0.0-SNAPSHOT.jar` (약 29MB)      | GPU 서버  | Ollama 중계 기능이 들어간 REST API      |
| 2   | `gemini-cli-ollama-0.61.0-<커밋>-win-x64.zip` (47MB) | 사용자 PC | Gemini CLI (Node 런타임·검색 도구 포함) |
| 3   | `gemini-cli-ollama-0.61.0-<커밋>-win-x64.zip.sha256` | 사용자 PC | zip 무결성 확인                         |

- 1번은 저장소에 없다. 개발 PC의 `C:\AI-Projects\SqltuneRestApi-반입-20261002`에
  있다(MD5 `91ed39f1927ac5411205e78d744dc7ba`).
- 2·3번은 인터넷망 PC에서 만든다.

  ```sh
  git pull
  npm ci
  bash scripts/ollama-offline/package.sh --target win-x64
  ```

  결과는 `dist-offline/`에 생긴다. 이름에 `-dirty`가 붙으면 커밋하지 않은 수정이
  섞인 것이니 반입하지 않는다.

## 2. GPU 서버: REST API jar 교체

REST API 설치 폴더(`.../SqltuneRestApi/app/sqlrestapi`)에서 작업한다. 서버가
2대면 두 서버 모두 한다.

```sh
cd <설치경로>/SqltuneRestApi/app/sqlrestapi

# 1) 기존 jar 백업
cp -p target/sqltune-rag-java-1.0.0-SNAPSHOT.jar target/sqltune-rag-java-1.0.0-SNAPSHOT.jar.bak-$(date +%Y%m%d)

# 2) 반입한 jar로 교체
cp <반입경로>/sqltune-rag-java-1.0.0-SNAPSHOT.jar target/

# 3) 재기동
./stop_server.sh
sleep 2
./start_server_prod.sh

# 4) 확인
curl -s http://localhost:9300/health
curl -s http://localhost:9300/ollama/api/version
curl -s http://localhost:9300/ollama/api/tags
```

기대 결과:

| 확인                  | 정상                                             |
| --------------------- | ------------------------------------------------ |
| `/health`             | `"status":"ok"`, `"llm_model":"qwen3-coder:30b"` |
| `/ollama/api/version` | `{"version":"..."}` (Ollama 버전)                |
| `/ollama/api/tags`    | 모델 목록에 `qwen3-coder:30b`가 있음             |

- 설정 파일·기동 스크립트·`prompts/`는 바꾸지 않는다. Ollama 주소는 기존
  `SQLTUNE_LLM_URL`(기본 `http://localhost:11434`)을 그대로 쓴다.
- 이 jar에는 중계 기능 외에 9월 14일(색인 시 한글 UTF-8), 9월
  29일(`num_ctx` 32768) 수정도 들어 있다. 서버 jar가 그보다 오래된 것이면 함께
  반영된다.
- 기존 기능(`/api/chat`, `/api/query`, `/api/query/stream`)은 그대로다. DBAgent
  쪽 수정은 없다.
- 되돌리기: 백업한 jar를 원래 이름으로 복사하고 재기동한다.

`/ollama/api/version`이 502와
`{"error":"Ollama(...)에 연결할 수 없습니다..."}`를 돌려주면 Ollama가 떠 있지
않거나 `SQLTUNE_LLM_URL`이 틀린 것이다.

## 3. 네트워크 확인

사용자 PC에서 GPU 서버 9300 포트로 HTTP가 되어야 한다. 사용자 PC에서:

```
curl http://<GPU서버>:9300/ollama/api/version
```

- 응답이 없으면 사용자 PC 대역 → GPU 서버 9300 방화벽 허용을 신청한다. 기존에
  9300이 DBAgent 서버에만 열려 있었다면 사용자 PC 대역은 따로 열어야 한다.
- Ollama(11434)는 열지 않는다.
- 중계에는 인증이 없다(기존 REST API와 같음). 9300에 닿는 PC는 누구나 모델을 쓸
  수 있으므로 방화벽에서 출발지를 필요한 대역으로 제한한다.

## 4. 사용자 PC: Gemini CLI 설치

1. zip 무결성 확인 (`.sha256` 파일의 값과 비교)

   ```
   certutil -hashfile gemini-cli-ollama-0.61.0-<커밋>-win-x64.zip SHA256
   ```

2. zip을 원하는 폴더에 푼다. 예: `C:\Tools\gemini-cli-ollama`
3. 푼 폴더에서 `install.cmd` 실행. `[2/3] Run check` 아래에 `0.61.0`이 나오면
   정상이다.
4. `config\gemini-env.cmd`를 메모장으로 열어 서버 주소를 고친다.
   `:9300/ollama`는 그대로 둔다.

   ```
   if not defined GEMINI_OLLAMA_BASE_URL set "GEMINI_OLLAMA_BASE_URL=http://<GPU서버>:9300/ollama"
   ```

   이 파일에는 한글을 넣지 않는다(cmd가 잘못 읽을 수 있다).

5. `bin` 폴더를 사용자 PATH에 추가한다. (설정 → "계정의 환경 변수 편집" → Path →
   새로 만들기 → `C:\Tools\gemini-cli-ollama\bin`) 추가한 뒤 VS Code와 터미널을
   다시 연다.

`install.cmd`는 `%USERPROFILE%\.gemini\settings.json`과 `GEMINI.md`가 없을 때만
샘플을 복사한다. 이미 있으면 그대로 두므로 `config\settings.json.sample`과
비교해 아래 항목을 옮긴다.

| 항목                                   | 값                  | 이유                          |
| -------------------------------------- | ------------------- | ----------------------------- |
| `security.auth.selectedType`           | `"ollama"`          | 인증 방식 선택 창이 뜨지 않게 |
| `general.enableAutoUpdate`             | `false`             | 폐쇄망에서 업데이트 시도 방지 |
| `general.enableAutoUpdateNotification` | `false`             | 〃                            |
| `privacy.usageStatisticsEnabled`       | `false`             | 외부 전송 시도 방지           |
| `tools.exclude`                        | 웹 검색·웹 가져오기 | 폐쇄망에서 쓸 수 없는 도구    |

서버가 2대일 때: 지금은 CLI에 주소를 하나만 줄 수 있다. 사용자별로 서버를 나눠
적거나, 앞단에 분산 장치(nginx 등)를 두고 그 주소를 적는다. 분산 방식은 아직
정하지 않았다.

## 5. 사용

VS Code에서 작업 폴더를 열고 터미널(PowerShell 또는 cmd)에서:

```
gemini                    대화형 (처음 실행하는 폴더는 신뢰 여부를 묻는다)
gemini -p "질문"           한 번 실행
```

- 도구(파일 읽기·쓰기, 셸 명령)는 **사용자 PC의 파일**을 다룬다. 서버 파일은
  다루지 않는다.
- 셸 명령은 PowerShell로 실행된다. 모델이 `ls -la` 같은 리눅스식 명령을 먼저
  시도했다가 오류를 보고 고쳐 쓰는 일이 있다.
- 첫 요청은 모델을 메모리에 올리느라 오래 걸릴 수 있다.

## 6. 적용 후 점검표

| #   | 점검                                               | 방법                                                            |
| --- | -------------------------------------------------- | --------------------------------------------------------------- |
| 1   | 서버 중계 동작                                     | 서버에서 `curl http://localhost:9300/ollama/api/version`        |
| 2   | PC → 서버 연결                                     | PC에서 `curl http://<GPU서버>:9300/ollama/api/version`          |
| 3   | CLI 실행                                           | `gemini --version` → `0.61.0`                                   |
| 4   | 한 번 실행                                         | `gemini -p "1+1은?"` → 한국어 답변                              |
| 5   | 도구 호출                                          | 작업 폴더에서 `gemini -p "이 폴더에 어떤 파일이 있는지 알려줘"` |
| 6   | 대화형: 글자가 실시간으로 나오는지, ESC로 멈추는지 | `gemini` 실행 후 긴 답변을 요청하고 ESC                         |
| 7   | 설명이 한국어로 나오는지                           | 파일 생성 같은 작업을 시켜 도구 호출 앞뒤 설명 확인             |
| 8   | 기존 기능 영향 없음                                | DBAgent의 AI DBA 챗봇·SQL 튜닝 화면 동작                        |

6·7번의 대화형 화면은 개발 PC에서도 직접 확인하지 못한 항목이다. 폐쇄망에서 처음
확인하게 된다.

## 7. 문제가 생기면

| 증상                                    | 확인                                                                                          |
| --------------------------------------- | --------------------------------------------------------------------------------------------- |
| `Ollama 서버(...)에 연결할 수 없습니다` | 3절 curl, `config\gemini-env.cmd`의 주소, 방화벽                                              |
| `Ollama 요청 실패 (404 /api/chat)`      | 서버 jar가 교체되지 않았다(중계 기능 없는 jar). 2절 다시                                      |
| 502 `Ollama(...)에 연결할 수 없습니다`  | 서버에서 Ollama가 떠 있는지, `SQLTUNE_LLM_URL`                                                |
| `모델 ...이(가) Ollama에 없습니다`      | `/ollama/api/tags`의 모델 이름과 `GEMINI_OLLAMA_MODEL`이 같은지                               |
| 인증 방식 선택 창이 뜸                  | `%USERPROFILE%\.gemini\settings.json`의 `security.auth.selectedType`                          |
| 답변이 한꺼번에 나오거나 중간에 끊김    | PC와 서버 사이에 프록시·분산 장치가 있으면 응답 버퍼링을 끄고 대기 시간을 600초 이상으로 한다 |
| 설명이 영어로 나옴                      | 이미 영어로 진행된 대화를 이어 간 경우다. 새 세션으로 시작한다                                |
| 설명이 가끔 중국어로 나옴               | 개발 PC에서 한 번 관찰됨(이후 턴은 한국어). 반복되면 기록해 둔다                              |
| SQL 튜닝 응답이 느려짐                  | CLI와 SQL 튜닝이 같은 Ollama를 쓴다. 동시 사용 시 대기가 생긴다                               |

서버 로그: `<설치경로>/SqltuneRestApi/app/sqlrestapi/app.log`
(`OllamaProxyController: ...` 줄이 중계 쪽 기록이다.
`stream ended early ... Broken pipe`는 사용자가 ESC로 끊은 경우에도 남는 정상
기록이다.)
