## 1. 패키지 상태에서 셸 명령 확인, node-pty 포함 여부 결정

배경: Windows 패키지에는 가상 터미널 모듈(node-pty)이 없다. 운영체제별
바이너리라 번들에서 제외(`esbuild.config.js`의 `external`)되고 패키지 zip에도
넣지 않았다. 없으면 CLI가 일반 프로세스 실행 방식으로 셸 명령을 돌린다.

| 항목                                            | node-pty 있음       | node-pty 없음 (지금 패키지)      |
| ----------------------------------------------- | ------------------- | -------------------------------- |
| 일반 명령 실행, 결과를 모델에 전달              | 동작                | 동작                             |
| 출력의 색상·진행률 표시                         | 터미널처럼 보임     | 글자만, 진행률 줄이 쌓일 수 있음 |
| 실행 중 키 입력이 필요한 명령(y/n, 비밀번호 등) | 박스 안에 입력 가능 | 입력을 못 받아 멈추거나 실패     |

할 일:

1. 패키지를 푼 상태(node-pty 없음)에서 셸 명령 도구를 실제로 돌려 본다. 지금까지
   패키지로 확인한 것은 파일 목록·읽기·검색뿐이고 셸 명령은 개발 실행기(node-pty
   있음)로만 확인했다.
   - 한글이 나오는 명령(예: 없는 옵션을 준 `Get-ChildItem`의 오류 메시지)의
     출력이 깨지지 않는지. node-pty 유무에 따라 인코딩 처리 경로가 다를 수 있다.
   - 대화형 화면의 박스 표시("매 개 변 수" 벌어짐 수정은 node-pty 경로의 것)
2. 결과에 따라 node-pty를 패키지에 넣을지 결정한다.
   - 넣는다면: `node_modules/@lydell/node-pty`와 `@lydell/node-pty-win32-x64`를
     패키지의 `bundle/node_modules/` 아래에 복사하도록 `package.sh` 수정(Linux
     대상은 `@lydell/node-pty-linux-x64`). 번들이 그 위치에서 찾는지 확인 필요.
   - 넣은 뒤 실행 중 입력이 필요한 명령으로 확인.
